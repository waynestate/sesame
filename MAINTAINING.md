# MAINTAINING: the care and feeding of the magic words

How to build, test, release and keep SESAME current. SESAME is the stack's auth library: it hands an app a verified
identity and leaves the session to the app. It is security code, so it changes slowly, on maintained libraries, with
tests for every refusal. Open sesame, but only for the right people.

## What SESAME is and what it depends on

- `waynestate/sesame` on Packagist. Framework-free core, with a Laravel adapter (service provider and
  `config/sesame.php`).
- Drivers: `fake` (local dev and tests), `cas` (CAS protocol 2.0 against Wayne State's CAS at `login.wayne.edu`), and
  `gateway` (accepts only a short signed JWT from a trusted proxy, such as Drawbridge). `oauth2` (bearer-token APIs) and `oidc` (browser sign-in, Entra first) ship now; `saml` ships too, opt-in (see the README driver table).
- Runtime dependencies: `lcobucci/jwt` (the gateway driver's signatures, never hand-rolled), `firebase/php-jwt` (key sets
  and the oauth2 and oidc token checks), `nyholm/psr7` and `nyholm/psr7-server`, `symfony/http-foundation`, PSR
  interfaces, `ext-simplexml`. The oidc driver needs `league/oauth2-client` and the saml driver `onelogin/php-saml`,
  both suggested, not required. No other stack package at runtime. Dev: PHPUnit, Pint and PHPStan with strict rules
  (presets from Pinstripe), Orchestra Testbench.
- **Who uses it:** apps generated by Sourdough, WELD, and any app moving off older CAS clients (Booster has a recipe).

## Where it lives

Development happens on git.wayne.edu, the canonical repository ([enterprise-apps/sesame](https://git.wayne.edu/enterprise-apps/sesame)).
Changes, issues and merge requests go there, and tags are made there, by the maintainer, with an approver.
GitHub ([waynestate/sesame](https://github.com/waynestate/sesame)) is a read-only push mirror: `main` and tags are
copied automatically, Packagist reads from it, and nobody pushes to it.

## Build and test

| Task | Command |
|---|---|
| Install | `composer install` |
| All checks (what CI runs) | `composer ci` |
| Only the tests | `composer test` |
| Fix code style | `composer fix` |
| Site accessibility gate (Preflight's checker at the CI tag, 320 and 1280 px with the reflow check, in Docker) | `scripts/a11y.sh` (Linux, macOS) or `scripts/a11y.ps1` (Windows) |

With only Docker (the same lines work in PowerShell and sh):

```
docker run --rm -v "${PWD}:/app" -w /app composer:2 composer install --no-interaction
docker run --rm -v "${PWD}:/app" -w /app php:8.3-cli vendor/bin/phpunit
docker run --rm -v "${PWD}:/app" -w /app php:8.4-cli vendor/bin/phpunit
docker run --rm -v "${PWD}:/app" -w /app php:8.5-cli vendor/bin/phpunit
docker run --rm -v "${PWD}:/app" -w /app composer:2 composer ci
```

`composer ci` runs `composer validate --strict`, the tests, Pint, PHPStan, the agent-ready check, the docs build check and `composer audit --locked`. On Windows,
if tests fail oddly after a Docker install, delete `vendor/` and install again.

## CI

- **GitLab:** Preflight's `php-test` (PHP 8.3, 8.4, 8.5) and `composer-audit` components, plus a `composer-ci` job.
- **GitHub:** `.github/workflows/ci.yml` calls Preflight's reusable workflow with `composer ci`.
- Green means `composer ci` passed on all three PHP versions on both.

## Where its settings come from

- **CAS:** the server URL and protocol version are config. Today Wayne State's CAS answers protocol 2.0. Its owner
  confirmed that a CAS sign-in means MFA happened for that session, which is what the opt-in `cas.assume_mfa` setting
  relies on, and the server is adding an `authenticationDate` attribute that SESAME uses as the sign-in time.
- **Gateway:** the trusted proxy range, the header name and the public key of the signer are config. SESAME accepts
  several keys by `kid` (`gateway.public_keys`, or the JWKS file Drawbridge publishes, `gateway.jwks_file`), so a key
  rotation needs no coordinated window; Drawbridge's ADR-0001 has the scheme.
- No secrets live in this repo. Test keys are generated by the tests.

## Changing it safely

- Every new refusal path gets a test. Fail closed: when in doubt, no identity.
- Never accept a plain identity header; PHP cannot tell `Remote-User` from `Remote_User`. The `gateway` driver takes
  a signed assertion only, with `jti` replay protection.
- Use maintained libraries for protocol and crypto work. Our code is the thin layer on top.
- A change to what the `gateway` driver accepts needs the same change in Drawbridge.

## Releasing

1. Move the lines under `## [Unreleased]` in `CHANGELOG.md` (Keep a Changelog) to a new `## [X.Y.Z] - YYYY-MM-DD`
   heading. (0.1.0 predates the heading convention, so it has none.)
2. `composer ci` green locally, then on both pipelines for that commit.
3. Run a secrets scan of the history and check that nothing internal (server names, people, IDs) is in the tree.
4. Tag `X.Y.Z` (no `v`) on git.wayne.edu. The mirror carries the tag to GitHub, and Packagist picks it up from there.
5. A release needs a maintainer's approval, and a security-relevant change deserves a second reviewer. Never move or
   delete a published tag.

## The front page
