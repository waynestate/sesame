Ticket 2 · Round trips

Seventy-five browsers, in and out

Each round trip is seven requests with a cookie jar: the protected page sends you to sign in, the login sends you to CAS, CAS sends you back with a ticket, the ticket is checked once and dropped from the address bar, the page knows you, the MFA check gives its reason, and logout clears you out.

What the MFA check answered

  • NO_AUTH_TIME59
  • SATISFIED8

What held

MFA was satisfied only when assume_mfa was on and CAS reported a sign-in within eight hours: 8 of 8. A sign-in ten hours old was TOO_OLD, a date in the future or no date at all was NO_AUTH_TIME, never a pass. All 32 foreign return-to addresses were replaced with the app's own URL. Every logout sent Cache-Control: no-store and Clear-Site-Data, and every next request was signed out.

The one it got wrong

An answer whose cas: prefix was bound to a different namespace was read as a success. The parser matched the prefix, not the namespace it promises to check. Such an answer could only come from the CAS server SESAME is configured to trust, over HTTPS, so the risk is small, but the code says namespace and should mean it. The fix and a test for this exact answer are queued before the next tag.

Ticket 4 · Cut your own

Run it on your own app

Install SESAME, wire the raw PHP path, and walk through the door with the fake driver on your machine.

Install

composer require waynestate/sesame

A sign-in page, raw PHP, local only

<?php require __DIR__ . '/../vendor/autoload.php'; session_start(); // build Sesame with DriverFactory::make(Config::fromArray([...])) as in the README, then: $user = sesame_login();

Serve it on a free port

php -S localhost:18921 -t public

The proof harness did exactly this inside php:8.4-cli with no network, swapping the CAS server for a stub client, and logged each unit as one line (tool commit, unit id, command, exit code, duration, outcome) in the stack's internal record.

Ticket 5 · Small print

What this does not prove

  • No real CAS server was contacted and no real account was used. The answers are synthetic, shaped from the protocol and from what Wayne State's server returns; a live sign-in is proved on a test site, not here.
  • It ran the raw PHP path. The Laravel path shares the same core and has its own tests, but these 75 round trips did not go through a Laravel app.
  • The gateway driver (signed assertions from a front proxy) was not part of this run.
  • Replay of a used ticket is the CAS server's job; the stub did not model it.
  • One tool error stands until the namespace fix ships. This page will say 150 when it does.
